⭐ PART 4 — When AI Makes Things Worse
(and How Senior Engineers Recover)

This is the part nobody talks about.

AI doesn't just speed you up.
Sometimes, it quietly makes things worse.

1. It Generates Bad or Over‑Engineered Code

Sometimes the output:

  • Doesn't fit your architecture
  • Uses patterns you'd never ship
  • Relies on non‑existent APIs
  • Is harder to maintain than writing it yourself

What I do:

Treat it as a draft.
Keep the ideas — rewrite the implementation.

2. It Refactors Large Features Poorly

Big refactors are where AI struggles most:

  • Loses context
  • Breaks types
  • Introduces subtle bugs
  • "Almost works"

What I do:

Break the refactor into small steps:

  • "Extract this logic into a helper."
  • "Rename this type and update all references."
  • "Split this reducer into two smaller ones."

AI is great at small, well‑framed changes — not giant rewrites.

3. It Forces You to Study the Code Anyway

Even when AI writes code, I still have to:
read → understand → validate → test → integrate.

What I do:

Ask AI to explain its own code:

  • "Explain this reducer step by step."
  • "What edge cases does this miss?"
  • "How would this behave after 8 hours?"

If it can't explain it clearly, I don't trust it.

4. It Gets Stuck in Loops

Sometimes it keeps:

  • Repeating the same pattern
  • Ignoring constraints
  • "Fixing" things by breaking others

What I do:

  • Reset context
  • Paste the exact file
  • State constraints
  • Show the failing test

The tighter the frame, the better the output.

The Reality

AI is powerful — but it's not a senior engineer.
It doesn't own architecture, trade‑offs, or long‑term maintenance.

That's still on us.
