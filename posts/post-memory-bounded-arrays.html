Memory‑Bounded Arrays
for Real‑Time Trading UIs

Real‑time applications behave very differently from typical web apps. A normal React app might fetch data once, store a few dozen items, and never grow beyond that.

A real‑time trading UI is the opposite:

  • ⚡ Trades stream in continuously
  • 📈 Order books update dozens of times per second
  • 🕒 Candles accumulate every minute
  • 🖥️ The app stays open for hours — sometimes entire trading sessions

If you store every update forever, your arrays grow like this:

  • 1 minute → 1,200 updates
  • 1 hour → 72,000 updates
  • 4 hours → 288,000 updates
  • 8 hours → 576,000 updates

And that’s per currency pair. Track 10 pairs and you’re easily in the millions of objects.

At that point:

  • The browser slows down
  • Garbage collection spikes
  • Memory usage explodes
  • Rendering becomes inconsistent
  • AG Grid and charts start choking
  • The UI becomes unresponsive

This is why unbounded arrays will kill the browser.

🛠️ What Memory‑Bounded Arrays Actually Do

A memory‑bounded array enforces a hard limit on how many items you keep.

const MAX_TRADES = 1000
if (trades.length > MAX_TRADES) {
  // Immediate memory release
  trades.splice(0, trades.length - MAX_TRADES)
}

This means:

  • You always keep the latest 1000 trades
  • You never store more than 1000
  • Memory usage stays predictable
  • Rendering cost stays stable
  • The app behaves the same after 5 minutes or 5 hours

This is the difference between a real‑time system and a demo app.

⚡ Why This Keeps the UI Responsive

1. Rendering cost stays constant

React, AG Grid, and Highcharts all scale poorly with huge arrays.

Keeping arrays capped means:

  • No exponential rendering cost
  • No slowdowns over time
  • No UI degradation after long sessions

2. Memory usage stays flat

Without limits, memory grows forever. With limits, memory looks like this:

  • Start → 50MB
  • 1 hour → 55MB
  • 8 hours → 60MB

Instead of:

  • Start → 50MB
  • 1 hour → 200MB
  • 8 hours → 1GB+ (browser crash)

3. Garbage collection stays predictable

Large arrays create GC spikes that freeze the UI. Bounded arrays avoid this entirely.

4. Charts and grids stay smooth

Highcharts and AG Grid both struggle with large datasets.

Capping arrays ensures:

  • Smooth scrolling
  • Fast sorting
  • Stable FPS
  • No jank

5. The app behaves the same after hours of use

A trading UI must be as fast at 4pm as it was at 9am. Memory‑bounded arrays guarantee that.

📏 The Principle Behind It

Real‑time systems don’t need infinite history — they need the most recent, relevant data.

  • Traders care about the last 1000 trades
  • Order books only need the current snapshot
  • Charts only need the last N candles

Everything else belongs in a backend database, not the browser. Memory‑bounded arrays prevent real‑time UIs from degrading over time.
